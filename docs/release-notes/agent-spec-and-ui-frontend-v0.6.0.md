# v0.6.0：业务 Agent 方案、UI/前端工作指南

## 摘要

相对 v0.5.0：做会调用模型的产品时，控制方式、记忆、知识库与召回要在 Spec 冻结前写进同一份 Spec；有终端界面的项目，布局有取舍时先交可点击原型，原型确认后推荐前端技术方案并等用户确认，视觉验收在真实产品入口上做。仍是 8 个 skill，不新增 skill，不预设技术栈。

## 主要变更

### 1) 业务 Agent 方案（PR #4）

- 新增按需读的 `reference/agent-design-guide.md`：控制方式、谁做决定、工具与业务技能、上下文与记忆、知识库与召回、运行边界、用户/调用方路径
- 触发条件：会调用模型，并且多步执行、调工具、跨轮保留信息，或回答依赖外部资料。宿主先检索、再交给模型答一次，也要写「知识库与召回」
- 单轮、无工具、不查外部资料：整节写「不需要」，不删节
- 有稳定编号时先精确匹配，匹配不到就失败关闭；搜索引擎和向量库是索引，不是事实真源
- 官方编程资料在框架选定并冻结后引进项目，不写进 Spec，也不预置进 playbook

### 2) 计划记决策与规格没点名的失败（PR #4）

- Issue 只记文件、签名、规格值和断言，不写函数体；拆完等人确认再写生产代码（spike 档以确认过的一句话意图为准）
- 每个 Issue 最多 5 条「规格未写、合理用户会踩」的失败并落到测试；检查过没有就写「无（已检查）」
- `verify-review`：这类失败缺测试按 P1，已伤到使用者按 P1 或 P0，不能因规格没写就降级
- `plan-spec`：猜测和技术选型标明谁拍板（「模型建议，待确认」）；冻结前用实现者视角分三堆

### 3) UI / 前端（PR #5）

- 新增按需读的 `reference/ui-frontend-guide.md`，从零开发和改版都适用
- 布局有取舍时先交可点击原型：唯一入口、版本、四种状态、按「页面、位置、控件、改什么、不改什么」复述、记录确认范围。改文案、调间距不做原型
- 原型确认后、冻结前，推荐一套前端技术方案（框架、分层、状态、接口、权限、样式、测试、发布方式），每项写理由、代价和没选什么，等用户确认。已有项目默认沿用现有栈
- 视觉验收在产品构建入口上做，不在设计预览或开发服务器上做：宽屏、常规、窄屏、短视口，加长内容；失败、超时、空数据、无权限显示确认过的状态
- 浏览器测试等应用自己的就绪信号；失败先分诊是装置问题还是产品问题；真实或共享环境的测试凭据在 finally 撤销并核对残留
- 第一个 Milestone 就真实走通一条路径，不先做全静态壳再统一接接口

### 4) 检查运行位置与索引维护（PR #5）

- PR 摘要加「检查与运行位置」：每项检查写 CI / 仅本地 / 未跑，不能用「CI 通过」概括没进 CI 的检查
- 阶段收尾时，项目已有 `CONTEXT_INDEX.md` 或同类索引的，更新「当前」条目；旧文件不改写正文，只在首行加「历史快照」标签
